## 已提交内容

- 修复未核实付款也能产生收益、重复资金入账、净收益计算、T+7 解冻及月结重复入账问题。

- 未接通的自动微信/支付宝支付、充值及退款明确返回渠道不可用，不再使用模拟成功路径。
- 修复本地启动涉及的 JSX、dayjs、SQLite 唯一索引及重复迁移问题。
- 收录当前源码中的 delta 风格普通单录入弹窗、报价/草稿/提交接口及模型。该部分为初版代码，不代表完整录单资金闭环已验收。
- [下单页面开发设计](order-entry-development.md)给出完整目标，包含多人分账、押金、优惠承担等后续要求。

## 验证与限制

本次推送前通过的后端测试包：

```sh
cd api
go test ./internal/service/finance ./internal/service/orderentry ./internal/service/order ./pkg/scheduler ./internal/handler/resp
```

财务测试使用临时 SQLite。本次重新执行上述五个后端测试包、API 编译及30项工资页面回归测试，均通过。API 编译使用 `go build -buildvcs=false`，仅关闭本机权限造成的 VCS 信息嵌入。没有执行真实资金交易。

重要限制：

- 自动支付渠道尚未接入真实商户；人工核账是对外部交易的登记，不等于银行自动验证。
- 普通录单接口和表单已存在，但不得据此声明多人、押金、打赏、优惠与工资入账已全面接通。
- 客户自助下单仍需独立开发及修复现有计价、订单组ID和模拟客户端问题。
- 完整前端 TypeScript/生产构建存在原项目错误，未完成全量通过验收。
- PostgreSQL迁移和并发集成验收尚未完成。
- 复用旧服务构造器时须保持 finance 依赖注入，避免走旧兼容逻辑。

## 本地运行

使用项目原有配置样例配置数据库和缓存。本地演示可使用 SQLite 与内存缓存；生产必须配置实际数据库、密钥和支付渠道，并独立进行迁移及资金验收。已有数据库在迁移前必须备份。

本次发布不包含本地数据库、运行日志、环境密钥、依赖目录或构建产物。原许可证及上游历史保留。
